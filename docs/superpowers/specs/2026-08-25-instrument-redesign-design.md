# ujinf.net 시각 개편 — 계측기 재해석

날짜: 2026-08-25
상태: 설계 승인됨 (구현 계획 대기)

## 배경

사이트의 정체성(굴림체 · 안티앨리어싱 끄기 · 별 배경 · 유리 카드)은 2000년대
한국 PC/게임 화면 감성으로, 버릴 자산이 아니다. 문제는 그 톤이 **전달되지
않는다**는 것과, 페이지 구조가 **위계를 만들지 못한다**는 것이다.

진단된 결함:

1. `--font-mono`의 GulimChe는 Windows 로컬 폰트라 맥/모바일에서 fallback된다.
   개성의 대부분이 절반 이상의 방문자에게 도달하지 않는다. (`styles.css:29`)
2. `.project-card` 하나가 히어로·본문·목록·솔버를 전부 겸해서, 페이지가
   동일한 상자의 수직 스택으로 읽힌다. (`styles.css:273`)
3. `projects.html`에 이미지가 한 장도 없다. 자율주행·텔레메트리를 다루는
   사람의 Work 페이지가 텍스트뿐이다.
4. 히어로 캔버스가 별/파티클이라 주제와 무관하다. 정작 사이트는 진짜 RK4
   궤적 적분기를 갖고 있다. (`hero.js`, `trajectory.js`)
5. 모든 요소가 `font-weight:400` 고정이라 대비 수단이 색뿐이다.
6. `--accent`(파랑)와 `--accent-3`(마젠타)가 배경·별·보더·제목·버튼에 전부
   섞여 있어, 궤적 범례에서 마젠타가 high arc를 뜻할 때 그 의미가 안 읽힌다.
7. 라이트 테마가 별을 끄고 유리를 지운 다크의 열화판이다. (`styles.css:654`)
8. `.result-table` / `.proof-callout` / `.result-strip`은 어디서도 안 쓰인다.
9. 검색/필터가 반쪽이다. `app.js:138-140`이 찾는 마크업이 HTML에 없다.

## 방향

**계측기(instrument)로 재해석한다.** 굴림체 톤은 유지하되 사이트 전체를
계기판 언어로 바꾼다.

설계가 진행되며 이 방향의 무게중심이 옮겨갔다. 처음에는 히어로에 놓을 하나의
시그니처(실시간 궤적)를 상정했으나, 그것은 폐기됐다. 정체성은 얹는 장치가
아니라 **바탕**이 진다 — 우주, 반투명 창, 굴림체. 사이트 주인이 실제로 쓰는
화면 그대로다. 나머지는 여백과 라벨의 정밀도로 승부한다.

## 1. 토큰

### 1.1 타이포 — 역할을 셋으로

**사이트 전체가 굴림체다.** 본문까지 포함해 한 서체로 간다.

| 역할 | 서체 | 쓰는 곳 |
|---|---|---|
| 표시 | 굴림체 → Neo둥근모 폴백 | h1·h2·h3, 섹션 라벨, 태그칩, 버튼 |
| 계기 | 굴림체 → Neo둥근모 Code 폴백 | 솔버 출력, 궤적 축·범례, 좌표, 수치 |
| 본문 | 굴림체 → Neo둥근모 폴백 | 문단, 목록, 캡션 |

따라서 아래 두 가지는 **현행 유지**로 되돌린다. 초기 설계에서 바꾸려 했으나
서체를 하나로 통일하면 근거가 사라진다.

- `-webkit-font-smoothing:none`을 페이지 전역에 유지한다. 본문도 비트맵
  서체이므로 스무딩을 걸 이유가 없다.
- 굵기는 400으로 고정하고 `font-synthesis:none`을 유지한다. 굴림체에는
  진짜 볼드가 없어서 합성 볼드는 비트맵을 뭉갠다. 강조는 색과 크기로 한다.

16px 굴림체는 긴 문단 가독성이 떨어진다는 점은 짚어 두었고, 그럼에도
서체 통일을 택했다. 본문 크기는 현행 16px을 유지한다.

**굴림체를 1순위로 둔다.** 굴림체가 깔린 기기는 지금과 똑같이 굴림체로
렌더링되고 웹폰트를 내려받지도 않는다 — 브라우저는 실제로 렌더링에 쓰이는
@font-face만 가져온다. 굴림체가 없는 맥·모바일에서만 Neo둥근모가 받아진다.
굴림체를 포기하지 않고도 개성이 절반의 방문자에게 도달하지 않는 문제가
사라진다. 대가는 Windows와 그 외에서 자간·메트릭이 달라진다는 것이다.

라이선스: Neo둥근모는 SIL Open Font License 1.1. 웹폰트 사용에 별도 계약이나
조회수 과금이 없다. 재판매만 금지. (https://neodgm.dalgona.dev/)

**타입 스케일은 48 / 32 / 24 / 16 / 12로 고정한다.**
Neo둥근모는 16px 설계의 비트맵 계열이라 비배수 크기에서 흐려진다. 굴림체가
선명한 크기는 이와 다르므로, 최종 확정은 굴림체가 깔린 기기의 렌더링을 보고
한다 — 프로토타입의 38px / 32px 비교 패널이 그 판단 자료다. 표시용 서체에
한해 `clamp()`를 쓰지 않는다.

현행 → 신규 매핑:

| 대상 | 현행 | 신규 |
|---|---|---|
| `h1` | 38px (`styles.css:229`) | 32px |
| `.hero-copy h1` | 26px (`styles.css:928`) | 32px, 모바일 24px |
| `h2` | 24px | 24px (유지) |
| `h3` | 19px | 16px |
| 본문 | 16px | 16px (유지, 시스템 스택) |
| 라벨 / 수치 | 13px | 12px |

`h1`이 38→32로 **작아진다.** 픽셀 서체는 선명할 때 커 보이므로 크기를
잃지 않는다. 모바일 `h1`은 31px(`styles.css:633`)에서 24px로 내린다.

같이 고치는 것:

### 1.2 히어로 제목은 확대한 비트맵이다

굴림체는 작은 크기에서만 내장 비트맵을 쓰고 큰 크기에서는 매끈한 아웃라인으로
렌더링된다. 즉 `font-size`를 키우면 픽셀감이 사라진다. 픽셀을 유지한 채 크게
쓰려면 **작게 그린 비트맵을 정수배로 확대**해야 한다.

히어로 제목만 이 처리를 받는다. 오프스크린 캔버스에 12px로 그린 뒤
`imageSmoothingEnabled = false`로 3배 확대해 표시 캔버스에 옮긴다. 배율은
`round(3 × devicePixelRatio)`로 정수 device pixel에 맞춰야 블록이 정사각을
유지한다.

대가와 대응:

- 캔버스라 드래그 선택과 페이지 내 검색이 안 된다. 실제 텍스트는 시각적으로만
  숨긴 `<span>`으로 DOM에 남긴다 — 스크린리더와 SEO가 읽고, `data-i18n`도
  그 노드에 걸리므로 i18n은 그대로 동작한다.
- 굴림체가 없는 기기에서는 Neo둥근모 비트맵이 대신 확대된다. 블록감은
  유지되지만 글자 모양은 달라진다.
- 타이프라이터는 글자마다 캔버스를 다시 그린다. 12px 한 줄이라 비용은 무시할
  수준이다.

배율(×2 / ×3 / ×4)과 적용 범위는 프로토타입에서 확인 후 확정한다. 현재
기본값은 **×3, 히어로 제목에만** 적용이다.

폰트는 서브셋하지 않는다. 프로토타입에서 실측한 결과 한글 전체를 포함한
`neodgm.woff2`가 **44KB**, `neodgm_code.woff2`가 **40KB**다. 비트맵 계열이라
압축이 잘 먹어서 서브셋 도구도 빌드 스텝도 필요 없다 — 받은 파일을 그대로
커밋한다. `font-display: swap`, 로드 실패 시 시스템 스택으로 폴백.

### 1.2 색 — 마젠타를 데이터에 돌려준다

```
--ink-0   #04050d   바탕
--ink-1   #0a0c1a   표면 (패널)
--ink-2   #141830   융기면 / 선
--signal  #4f7dff   상호작용 전용 — 링크, 포커스, 주 버튼, 현재 위치
--data-hi #d55cff   데이터 전용 — high arc, 보조 계열
--alert   #ffb648   상태 — 솔버 수렴 실패, 경고
--text    #e6ecff
--muted   #93a0cc
```

규칙: **파랑이면 누를 수 있는 것, 마젠타면 데이터, 주황이면 상태.**
배경 그라디언트와 별에서는 이 세 색을 강조로 쓰지 않는다 — 하늘은 하늘이고,
신호는 신호다. 그래야 규칙이 페이지 전체에서 깨지지 않는다.

**토큰 이름을 바꾸므로 JS도 같이 고쳐야 한다.** 캔버스가 CSS 변수를 직접
읽는다: `trajectory.js:71-74`(`--accent`, `--accent-3`, `--muted`,
`--border-soft`), `hero.js:51-52`(`--accent`, `--accent-3`). 구 이름을
별칭으로 남기지 않고 참조를 전부 교체한다 — 별칭을 남기면 "마젠타는
데이터"라는 규칙이 다시 흐려진다.

## 2. 히어로 — 장치를 두지 않는다

궤적 히어로는 폐기했다. 실제로 렌더링해 본 결과 난잡했다. 카피와 사진 위에
아크 다발과 눈금과 수치가 겹치면서, 정보가 늘어난 게 아니라 시선이 갈 곳을
잃었다.

히어로에는 시각 장치를 두지 않는다. 이름, 타이핑되는 한 줄, 문장 둘, 버튼
둘, 사진 하나. 그게 전부다.

**정체성은 히어로가 아니라 바탕이 진다.** 우주 + 반투명 창 + 굴림체 —
이 셋은 사이트 주인이 실제로 쓰는 화면이고, 페이지 어디에나 이미 깔려 있다.
따로 시그니처를 만들어 얹을 필요가 없었다.

그래서 `hero.js`는 재작성이 아니라 **파티클 부분을 삭제**한다. 타이프라이터만
남긴다. 프론트 RK4 사본이 둘로 늘어날 일이 없으므로 `ballistic-core.js`
추출도 불필요하다 — `trajectory.js`는 지금 형태 그대로 솔버 페이지에 남는다.

## 2.1 바탕 — 우주와 반투명

정체성을 지는 것이 바탕이므로, 바탕의 요구사항을 명시한다.

**별 배경은 유지한다.** 초기 설계에서 "궤적과 경쟁한다"는 이유로 제거하려
했으나 철회했다. 별은 장식이 아니라 이 사이트 주인의 취향이다 — 늘 우주
배경화면을 쓰고, 터미널은 반투명에 굴림체로 고집한다. 원래의 다크 + 유리 +
별 조합은 그 화면을 그대로 옮긴 것이었다.

**드리프트와 반짝임(`stars-drift`, `stars-drift2`, `stars-twinkle`)도
유지한다.** 한때 궤적과 경쟁한다는 이유로 정지시키려 했으나, 궤적이
폐기되면서 근거가 사라졌다. 경쟁할 상대가 없으면 정지시킬 이유도 없다.
`prefers-reduced-motion`에서만 멈춘다.

**반투명은 장식이 아니라 장치다.** 뒤의 별과 성운이 실제로 비쳐 보여야 한다.
뒤에 아무것도 없으면 반투명은 그냥 회색 유리다 — 별이 있어야 "뒤에 우주가
있다"를 보여주는 장치가 된다. 이것이 별을 되살린 두 번째 이유다.

**투명도만 낮춰서는 반투명이 읽히지 않는다.** 프로토타입에서 실제로 겪었다.
알파 0.5로 낮췄는데도 불투명해 보였다 — 거의 검은 배경 위에 반투명 패널을
얹으면 검정과 검정이 겹칠 뿐이기 때문이다. **뒤가 밝아야 앞이 투명해 보인다.**
셋을 함께 조정해야 한다:

- 성운 라디얼 그라디언트를 뚜렷하게 (알파 0.20–0.34, 화면 대부분을 덮는 크기).
  배경이 균일한 검정이면 투과할 것이 없다.
- 별 레이어 불투명도를 0.6 안팎까지 올린다.
- 패널 알파를 0.30–0.40까지 더 내리고 `backdrop-filter: blur(14px)
  saturate(1.15)`를 얹는다. saturate가 뒤의 색을 살려 유리 너머라는 인상을
  만든다.

헤더·히어로·타일·결정 패널 모두 같은 처리를 받는다. 창이 하나만 투명하면
그것은 창이 아니라 예외로 보인다.

두 테마가 각자의 세계를 갖는다:

- **다크 = 우주.** 반짝이는 별 두 겹, 성운 라디얼 그라디언트, 창처럼 비치는
  반투명 패널.
- **라이트 = 모눈종이.** 별은 끄고(`--stars: 0`) 그리드를 올려 그래프용지로
  쓴다. 패널은 종이와 잉크 선.

움직이는 것은 타이프라이터와 별의 반짝임뿐이다. 둘 다 조용하고, 서로
경쟁하지 않는다.

## 3. 구조 — 상자를 줄이고, 남는 상자는 격자 안에만

`.project-card` 하나를 셋으로 나눈다.

| 등급 | 클래스 | 성격 | 규칙 |
|---|---|---|---|
| ① | `.panel--hero` | 유리 + 캔버스 | 페이지당 하나 |
| ② | `.panel` | 테두리 없음. 라벨 + 규칙선 | 본문 섹션 전부 |
| ③ | `.tile` | 실제 면을 가진 유일한 요소 | 반복 격자 안에서만 |

②의 헤더는 `BACKGROUND ─────────────` 형태로, 라벨은 계기 서체 대문자
`--muted`, 오른쪽으로 hairline이 끝까지 간다. 계기판에서 구역을 나누는 것은
상자가 아니라 눈금선이다. 면을 가진 ③은 반복 격자 안에서만 등장하므로
상자가 리듬을 만들지 방해하지 않는다.

`.eyebrow`(`styles.css:294`)는 ②의 섹션 라벨로 흡수한다.

### now.html

### projects/ballistic-solver.html
계기 언어의 본산이다.
- 솔버 폼 `legend`를 ② 라벨 언어로 통일
- 솔버 출력에 색 규칙 적용: 값은 `--text`, 라벨은 `--signal`, 수렴 실패
  상태는 `--alert`

## 5. 라이트 테마 — 모눈종이와 잉크

다크의 채도를 낮춘 판이 아니라 대응하는 자기 언어를 갖는다.

- 4px 그리드를 다크보다 진하게 올려 그래프용지로 만든다
- 유리 패널 대신 흰 종이 + 잉크 hairline
- 히어로 궤적은 종이 위의 어두운 잉크 선
- 패널 라벨선도 잉크 hairline

## 6. 품질 바닥선

- `prefers-reduced-motion`: 별 애니메이션 정지, 타이프라이터는 전문 즉시
  표시, reveal 즉시 표시, transition 없음
  (기존 동작 유지)
- 키보드 포커스: 태그 칩 포함 모든 인터랙티브 요소에 visible focus
- 반응형: 320px까지. ③ 격자는 1열, 솔버 폼은 2열
- i18n: 새로 생기는 라벨은 전부 `data-i18n` + `ko.json` 키 추가
  (README 규칙). 영어는 HTML에 남는다.
- 헤더/푸터는 계속 페이지마다 인라인 (README 규칙)
- 빌드 스텝 없음 유지

## 7. 삭제 대상

- `.result-table` / `.proof-callout` / `.result-strip` (`styles.css:374-437`) — 미사용
- `hero.js`의 파티클 구현 전체 (타이프라이터는 유지)
- `app.js`의 검색창 입력 참조 (태그 칩 필터는 유지)

## 8. 리스크

- **정수배 크기 강제**: 표시용 서체에 `clamp()`를 못 쓴다. 반응형은 스케일
  단계 전환으로 처리해야 하므로 중간 뷰포트에서 조정이 필요하다.
- **확대 비트맵 제목**: 캔버스라 선택·검색이 안 된다. 숨긴 실제 텍스트로
  스크린리더와 i18n은 확보하지만, 사용자가 제목을 복사할 수는 없다.
- **굴림체 본문 가독성**: 16px 굴림체는 긴 문단에서 읽기 부담이 있다.
  서체 통일을 우선한 의도적 선택이다.
- **SVG 썸네일은 실제 결과물이 아니다.** 신뢰도 면에서 스크린샷보다 약하다.
  교체 전제로 간다.
- **전 페이지 마크업 교체**: HTML 5개의 클래스가 전부 바뀐다. i18n 키가
  깨지지 않도록 `data-i18n` 속성 보존을 확인해야 한다.
- **mp4 프레임 추출**은 로컬에 ffmpeg가 있어야 한다. 없으면 SVG 도식으로
  대체한다.
