# ujinf.net 시각 개편 — 계측기 재해석

날짜: 2026-08-25
상태: 설계 승인됨 (구현 계획 대기)

## 배경

사이트의 정체성(굴림체 · 안티앨리어싱 끄기 · 별 배경 · 유리 카드)은 2000년대
한국 PC/게임 화면 감성으로, 버릴 자산이 아니다. 문제는 그 톤이 **전달되지
않는다**는 것과, 페이지 구조가 **위계를 만들지 못한다**는 것이다.

진단된 결함:

1. `--font-mono`의 GulimChe는 Windows 로컬 폰트라 맥/모바일에서 fallback된다.
   개성의 대부분이 절반 이상의 방문자에게 도달하지 않는다. (`styles.css:29`)
2. `.project-card` 하나가 히어로·본문·목록·솔버를 전부 겸해서, 페이지가
   동일한 상자의 수직 스택으로 읽힌다. (`styles.css:273`)
3. `projects.html`에 이미지가 한 장도 없다. 자율주행·텔레메트리를 다루는
   사람의 Work 페이지가 텍스트뿐이다.
4. 히어로 캔버스가 별/파티클이라 주제와 무관하다. 정작 사이트는 진짜 RK4
   궤적 적분기를 갖고 있다. (`hero.js`, `trajectory.js`)
5. 모든 요소가 `font-weight:400` 고정이라 대비 수단이 색뿐이다.
6. `--accent`(파랑)와 `--accent-3`(마젠타)가 배경·별·보더·제목·버튼에 전부
   섞여 있어, 궤적 범례에서 마젠타가 high arc를 뜻할 때 그 의미가 안 읽힌다.
7. 라이트 테마가 별을 끄고 유리를 지운 다크의 열화판이다. (`styles.css:654`)
8. `.result-table` / `.proof-callout` / `.result-strip`은 어디서도 안 쓰인다.
9. 검색/필터가 반쪽이다. `app.js:138-140`이 찾는 마크업이 HTML에 없다.

## 방향

**계측기(instrument)로 재해석한다.** 굴림체/픽셀 톤은 유지하되 사이트 전체를
계기판 언어로 바꾼다. 단 대담함은 한 곳에만 쓴다 — 히어로가 유일한 시그니처이고
나머지는 여백과 라벨의 정밀도로 승부한다.

## 1. 토큰

### 1.1 타이포 — 역할을 셋으로

| 역할 | 서체 | 쓰는 곳 |
|---|---|---|
| 표시 | Neo둥근모 (self-host) | h1·h2·h3, 섹션 라벨, 태그칩, 버튼 |
| 계기 | Neo둥근모 Code (self-host) | 솔버 출력, 궤적 축·범례, 좌표, 수치 |
| 본문 | 시스템 스택 | 문단, 목록, 캡션 |

라이선스: Neo둥근모는 SIL Open Font License 1.1. 웹폰트 사용에 별도 계약이나
조회수 과금이 없다. 재판매만 금지. (https://neodgm.dalgona.dev/)

**타입 스케일은 16px의 정수배로 고정한다: 48 / 32 / 24 / 16 / 12.**
Neo둥근모는 16px 설계의 비트맵 계열이라 비배수 크기에서 흐려진다. 현행
38 / 24 / 19는 정확히 그 흐려지는 크기다. 표시용 서체에 한해 `clamp()`를
쓰지 않는다 — 반응형은 스케일 단계를 갈아타는 방식으로 처리한다.

현행 → 신규 매핑:

| 대상 | 현행 | 신규 |
|---|---|---|
| `h1` | 38px (`styles.css:229`) | 32px |
| `.hero-copy h1` | 26px (`styles.css:928`) | 32px, 모바일 24px |
| `h2` | 24px | 24px (유지) |
| `h3` | 19px | 16px |
| 본문 | 16px | 16px (유지, 시스템 스택) |
| 라벨 / 수치 | 13px | 12px |

`h1`이 38→32로 **작아진다.** 픽셀 서체는 선명할 때 커 보이므로 크기를
잃지 않는다. 모바일 `h1`은 31px(`styles.css:633`)에서 24px로 내린다.

같이 고치는 것:

- `-webkit-font-smoothing:none`을 `body` 전역(`styles.css:63`)에서 걷어내고
  픽셀 서체에만 건다. 지금은 본문까지 거칠어져 있다.
- 본문에서 굵기를 해금한다. `b`/`strong`이 실제로 굵어져야 강조가 색에
  기대지 않는다. 표시용 Neo둥근모는 단일 굵기이므로 크기·자간·라벨로
  대비를 만든다.

폰트는 실제 쓰는 글자만 서브셋해 **한 번 만들어 커밋**한다(빌드 스텝 없음
유지). `font-display: swap`, 로드 실패 시 시스템 스택으로 폴백.

### 1.2 색 — 마젠타를 데이터에 돌려준다

```
--ink-0   #04050d   바탕
--ink-1   #0a0c1a   표면 (패널)
--ink-2   #141830   융기면 / 선
--signal  #4f7dff   상호작용 전용 — 링크, 포커스, 주 버튼, 현재 위치
--data-hi #d55cff   데이터 전용 — high arc, 보조 계열
--alert   #ffb648   상태 — 솔버 수렴 실패, 경고
--text    #e6ecff
--muted   #93a0cc
```

규칙: **파랑이면 누를 수 있는 것, 마젠타면 데이터, 주황이면 상태.**
배경 그라디언트에서 보라를 빼고 별을 궤적으로 교체하면 이 규칙이 페이지
전체에서 깨지지 않는다.

**토큰 이름을 바꾸므로 JS도 같이 고쳐야 한다.** 캔버스가 CSS 변수를 직접
읽는다: `trajectory.js:71-74`(`--accent`, `--accent-3`, `--muted`,
`--border-soft`), `hero.js:51-52`(`--accent`, `--accent-3`). 구 이름을
별칭으로 남기지 않고 참조를 전부 교체한다 — 별칭을 남기면 "마젠타는
데이터"라는 규칙이 다시 흐려진다.

## 2. 시그니처 — 히어로를 "사거리"로

`hero.js`를 다시 쓴다. 현행은 파티클 최대 90개를 매 프레임 전부 짝지어
검사하고(`hero.js:105-121`, n² ≈ 4000회/프레임) 별을 그린다. 비용은 쓰면서
주제는 말하지 않는다.

새 히어로는 **실제 RK4로 궤적을 적분해 그린다.**

- 좌하단에서 한 발이 출발해 아크를 그리며 날아가고, 궤적은 옅은 잔상으로
  남는다. 몇 초마다 조건(속도·항력·바람)이 바뀌며 새 아크가 겹쳐 아크
  다발을 이룬다.
- 마우스는 바람 벡터를 바꾼다. 다음 아크가 실제로 휜다.
- 바닥에 사거리 눈금, 좌하단에 계기 서체로 현재 파라미터
  (`v0 80 m/s   k 3.5e-4   wind 4.0 m/s`).

성능은 개선된다. 적분은 아크당 한 번 하고 폴리라인을 캐시한다. 매 프레임은
캐시된 선을 따라 그리기만 하므로 n² 루프가 사라진다.

물리 코드는 `trajectory.js`에서 `public/ballistic-core.js`로 추출해 히어로와
공유한다. 프론트 RK4 사본이 둘로 늘어나는 것을 막는다. Worker
(`functions/api/ballistic.js`)와 모델을 맞춰야 하는 기존 제약은 유지된다.

**별 배경을 제거한다** (`styles.css:71-108`, `--star-op1/2`). 궤적과 경쟁하기
때문이다. 바탕에는 기존 4px 그리드만 남겨 모눈종이로 쓰고, 다크/라이트 공통
기반으로 삼는다.

`prefers-reduced-motion`에서는 아크 3개를 정지 상태로 한 번만 그린다.

## 3. 구조 — 상자를 줄이고, 남는 상자는 격자 안에만

`.project-card` 하나를 셋으로 나눈다.

| 등급 | 클래스 | 성격 | 규칙 |
|---|---|---|---|
| ① | `.panel--hero` | 유리 + 캔버스 | 페이지당 하나 |
| ② | `.panel` | 테두리 없음. 라벨 + 규칙선 | 본문 섹션 전부 |
| ③ | `.tile` | 실제 면을 가진 유일한 요소 | 반복 격자 안에서만 |

②의 헤더는 `BACKGROUND ─────────────` 형태로, 라벨은 계기 서체 대문자
`--muted`, 오른쪽으로 hairline이 끝까지 간다. 계기판에서 구역을 나누는 것은
상자가 아니라 눈금선이다. 면을 가진 ③은 반복 격자 안에서만 등장하므로
상자가 리듬을 만들지 방해하지 않는다.

`.eyebrow`(`styles.css:294`)는 ②의 섹션 라벨로 흡수한다.

## 4. 페이지별 적용

### index.html
- ① 사거리 히어로 + `hero-split`(rviz-hero 사진 유지)
- ② Background
- ② What I work on → ③ 격자 6개, 썸네일 포함. 데스크톱 3열 / 태블릿 2열 / 모바일 1열
- ② Right now
- 인라인 `style` 4곳 토큰화

### projects.html
- ② intro
- 태그 칩 필터를 살린다: 자율주행 · 솔버 · 텔레메트리 · 비전.
  `.tag-chip`과 `data-search-item` 마크업을 추가한다. **검색창은 만들지
  않는다** — 프로젝트 5~6개에 과잉이다. `app.js`의 `#project-search-input`
  참조는 없어도 동작하도록 optional 처리한다.
- ③ 격자 5개 + 썸네일

### 썸네일 (혼합 전략)
리포에 있으나 배포에 안 들어가는 자산을 `public/`으로 옮겨 쓰고, 빈칸은
프로젝트별 미니 계기 도식을 SVG로 그려 채운다.

| 프로젝트 | 썸네일 |
|---|---|
| ballistic-solver | SVG 궤적 아크 |
| Mapless Autonomous Parking | `assets/videos/autopark_demo.mp4`에서 정지 프레임 추출, 실패 시 SVG 점유격자 도식 |
| HERO | SVG 비전 도식 |
| Racing Telemetry Stack | SVG 스파크라인 |
| Racing Analyze GUI | `assets/images/racing_analyze_gui.png` 이동 |

SVG 도식은 실제 결과물이 아니므로, 나중에 스크린샷을 받으면 교체하는 것을
전제로 한다.

### about.html
- `float:right` 사진(`styles.css:895`)을 걷어내고 2열 그리드(사진 | 소개),
  모바일 1열
- "What I'm doing" 목록은 연도가 붙은 실제 시퀀스이므로 타임라인 축(눈금선)을
  쓴다. 순서 장치는 순서가 정보일 때만 정당하다 — 여기는 정당하다.
- 나머지는 ② 라벨 섹션

### now.html
- "What I use"의 가운뎃점 나열을 태그 칩 격자로 바꾼다. `projects.html`의
  칩 언어를 재사용한다.
- "Last updated"는 계기 서체 수치로

### projects/ballistic-solver.html
계기 언어의 본산이다.
- 솔버 폼 `legend`를 ② 라벨 언어로 통일
- 솔버 출력에 색 규칙 적용: 값은 `--text`, 라벨은 `--signal`, 수렴 실패
  상태는 `--alert`
- 궤적 캔버스 축·범례를 계기 서체로. 범례 색을 `--accent`/`--accent-3`에서
  `--signal`/`--data-hi`로 교체

## 5. 라이트 테마 — 모눈종이와 잉크

다크의 채도를 낮춘 판이 아니라 대응하는 자기 언어를 갖는다.

- 4px 그리드를 다크보다 진하게 올려 그래프용지로 만든다
- 유리 패널 대신 흰 종이 + 잉크 hairline
- 히어로 궤적은 종이 위의 어두운 잉크 선
- 패널 라벨선도 잉크 hairline

## 6. 품질 바닥선

- `prefers-reduced-motion`: 히어로 정지, reveal 즉시 표시, transition 없음
  (기존 동작 유지)
- 키보드 포커스: 태그 칩 포함 모든 인터랙티브 요소에 visible focus
- 반응형: 320px까지. ③ 격자는 1열, 솔버 폼은 2열
- i18n: 새로 생기는 라벨은 전부 `data-i18n` + `ko.json` 키 추가
  (README 규칙). 영어는 HTML에 남는다.
- 헤더/푸터는 계속 페이지마다 인라인 (README 규칙)
- 빌드 스텝 없음 유지

## 7. 삭제 대상

- `.result-table` / `.proof-callout` / `.result-strip` (`styles.css:374-437`) — 미사용
- `body::before` / `body::after` 별 배경, `--star-op1` / `--star-op2`
- `hero.js`의 파티클 구현 전체
- `app.js`의 검색창 입력 참조 (태그 칩 필터는 유지)

## 8. 리스크

- **폰트 서브셋 유지비**: 카피를 크게 바꾸면 서브셋을 다시 만들어야 한다.
  빌드 스텝을 안 두는 대가다.
- **정수배 크기 강제**: 표시용 서체에 `clamp()`를 못 쓴다. 반응형은 스케일
  단계 전환으로 처리해야 하므로 중간 뷰포트에서 조정이 필요하다.
- **SVG 썸네일은 실제 결과물이 아니다.** 신뢰도 면에서 스크린샷보다 약하다.
  교체 전제로 간다.
- **전 페이지 마크업 교체**: HTML 5개의 클래스가 전부 바뀐다. i18n 키가
  깨지지 않도록 `data-i18n` 속성 보존을 확인해야 한다.
- **mp4 프레임 추출**은 로컬에 ffmpeg가 있어야 한다. 없으면 SVG 도식으로
  대체한다.
